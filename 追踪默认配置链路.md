# 追踪“编辑 Store 默认配置”的完整链路

## 一、完整数据流链路概览

当管理员在 Dashboard 中修改 `default_region_id`、`default_sales_channel_id`、`default_location_id` 和默认币种时，数据遵循以下链路流动：

```
前端表单 (React Hook Form)
    ↓
useUpdateStore Hook
    ↓
SDK 调用 (sdk.admin.store.update)
    ↓
API 路由 (POST /admin/stores/:id)
    ↓
Workflow (updateStoresWorkflow)
    ├── updateStoresStep (更新 Store 本体)
    └── updatePricePreferencesAsArrayStep (更新 Price Preferences)
    ↓
Store Module Service (业务验证 + 数据库操作)
    ↓
数据库 (Store 表 + StoreCurrency 表 + PricePreference 表)
```

```typescript
    result[0].id,
    req.scope,
    req.queryConfig.fields
  )

  res.status(200).json({ store })
}
```

### 3. Workflow 层

**文件位置**: `packages/core/core-flows/src/store/workflows/update-stores.ts`

#### 3.1 Workflow 定义

```typescript
export const updateStoresWorkflow = createWorkflow(
  updateStoresWorkflowId,
  (
    input: WorkflowData<StoreWorkflow.UpdateStoreWorkflowInput>
  ): WorkflowResponse<UpdateStoresWorkflowOutput> => {
    // 第一步：规范化输入，分离 is_tax_inclusive 到 price preferences
    const normalizedInput = transform({ input }, (data) => {
      if (!data.input.update.supported_currencies?.length) {
        return data.input
      }

      return {
        selector: data.input.selector,
        update: {
          ...data.input.update,
          supported_currencies: data.input.update.supported_currencies.map(
            (currency) => {
              return {
                currency_code: currency.currency_code,
                is_default: currency.is_default,
              }
            }
          ),
        },
      }
    })

    // 第二步：更新 Store 本体
    const stores = updateStoresStep(normalizedInput)

    // 第三步（条件）：如果有 supported_currencies，更新价格偏好
    when({ input }, (data) => {
      return !!data.input.update.supported_currencies?.length
    }).then(() => {
      const upsertPricePreferences = transform({ input }, (data) => {
        return data.input.update.supported_currencies!.map((currency) => {
          return {
            attribute: "currency_code",
            value: currency.currency_code,
            is_tax_inclusive: currency.is_tax_inclusive,
          }
        })
      })

      updatePricePreferencesAsArrayStep(upsertPricePreferences)
    })

    return new WorkflowResponse(stores)
  }
)
```

```typescript
export const updateStoresStep = createStep(
  updateStoresStepId,
  async (data: UpdateStoresStepInput, { container }) => {
    const service = container.resolve<IStoreModuleService>(Modules.STORE)

    const { selects, relations } = getSelectsAndRelationsFromObjectArray([
      data.update,

      select: selects,
      relations,

    await service.upsertStores(
      prevData.map((r) => ({
        ...r,
        metadata: r.metadata || undefined,

  }
)
```

#### 4.2 updatePricePreferencesAsArrayStep

**文件位置**: `packages/core/core-flows/src/pricing/steps/update-price-preferences-as-array.ts`

```typescript
export const updatePricePreferencesAsArrayStep = createStep(
  updatePricePreferencesAsArrayStepId,
  async (input: UpdatePricePreferencesAsArrayStepInput, { container }) => {
    const service = container.resolve<IPricingModuleService>(Modules.PRICING)

    if (!input.length) {
      return new StepResponse([], { prevData: [], newDataIds: [] })
    }

    // 查询现有的 price preferences
    const prevData = await service.listPricePreferences({
      $or: input.map((entry) => {
        if (!entry.attribute || !entry.value) {
          throw new MedusaError(
            MedusaError.Types.INVALID_DATA,
            "Attribute and value must be provided when updating price preferences"
          )
        }

        return { attribute: entry.attribute, value: entry.value }
      }, {}),
    })

    // 构建 upsert 数据
    const toUpsert = input.map((entry) => {
      const prevEntry = prevData.find(
        (prevEntry) =>
          prevEntry.attribute === entry.attribute &&
          prevEntry.value === entry.value
      )
      return {
        id: prevEntry?.id,
        attribute: entry.attribute,
        value: entry.value,
        is_tax_inclusive: entry.is_tax_inclusive ?? prevEntry?.is_tax_inclusive,
      }
    })

    const upsertedPricePreferences = await service.upsertPricePreferences(
      toUpsert
    )

    return new StepResponse(upsertedPricePreferences, {
      prevData,
      newDataIds: arrayDifference(
        upsertedPricePreferences.map((p) => p.id),
        prevData.map((p) => p.id)
      ),
    })
  },
  // 补偿函数
  async (compensationData, { container }) => {
    if (!compensationData) {
      return
    }

    const service = container.resolve<IPricingModuleService>(Modules.PRICING)

    await service.upsertPricePreferences(compensationData.prevData)
    await service.deletePricePreferences(compensationData.newDataIds)
  }
)
```

```typescript
async updateStores(
  idOrSelector: string | StoreTypes.FilterableStoreProps,
  data: StoreTypes.UpdateStoreDTO,
  @MedusaContext() sharedContext: Context = {}
): Promise<StoreTypes.StoreDTO | StoreTypes.StoreDTO[]> {
  let normalizedInput: UpdateStoreInput[] = []
  if (isString(idOrSelector)) {
    normalizedInput = [{ id: idOrSelector, ...data }]
  } else {
    const stores = await this.storeService_.list(
      idOrSelector,
      {},
      sharedContext
    )

    normalizedInput = stores.map((store) => ({
      id: store.id,
      ...data,
    }))
  }

  const updateResult = await this.update_(normalizedInput, sharedContext)

  const stores = await this.baseRepository_.serialize<
    StoreTypes.StoreDTO[] | StoreTypes.StoreDTO
  >(updateResult)

  return isString(idOrSelector) ? stores[0] : stores
}
```

#### 5.3 核心验证逻辑（重点！）

```typescript
private static validateCreateRequest(
  stores: StoreTypes.CreateStoreDTO[] | StoreTypes.UpdateStoreDTO[]
) {
  for (const store of stores) {
    if (store.supported_currencies?.length) {
      // 验证 1: 检查是否有重复的 currency code
      StoreModuleService.validateUnique(
        store.supported_currencies.map((currency) => currency.currency_code),
        "currency"
      )

      // 验证 2: 检查是否有多个默认币种（这里抛出错误！）
      let seenDefault = false
      store.supported_currencies.forEach((currency) => {
        if (currency.is_default) {
          if (seenDefault) {
            throw new MedusaError(
              MedusaError.Types.INVALID_DATA,
              `Only one default currency is allowed`
            )
          }
          seenDefault = true
        }
      })

      // 验证 3: 检查是否设置了默认币种
      if (!seenDefault) {
        throw new MedusaError(
          MedusaError.Types.INVALID_DATA,
          `There should be a default currency set for the store`
        )
      }
    }

    if (store.supported_locales?.length) {
      StoreModuleService.validateUnique(
        store.supported_locales.map((locale) => locale.locale_code),
        "locale"
      )
    }
  }
}
```

## 四、关于"多个默认币种"错误的深入分析

### 4.1 错误抛出位置

错误在 **Store Module Service 层** 的 `validateCreateRequest` 方法中抛出：

```typescript
let seenDefault = false
store.supported_currencies.forEach((currency) => {
  if (currency.is_default) {
    if (seenDefault) {
      throw new MedusaError(
        MedusaError.Types.INVALID_DATA,
        `Only one default currency is allowed`
      )
    }
    seenDefault = true
  }
})
```
`store-module-service.ts:236-247`

### 4.2 为什么前端不"兜底"？

从前端代码分析：

```typescript
supported_currencies: store.supported_currencies?.map((c) => ({
  ...c,
  is_default: c.currency_code === default_currency_code,
})),
```
`edit-store-form.tsx:80-83`

前端的转换逻辑是：**对于每一个币种，设置 `is_default` 等于 `c.currency_code === default_currency_code`**。

理论上，这个逻辑保证了：
- 只有一个币种会满足 `c.currency_code === default_currency_code`
- 因此只有一个币种的 `is_default` 会是 `true`

**那为什么后端还要验证？**

### 4.3 后端验证的必要性（单一可信源）

虽然前端逻辑看起来是安全的，但后端验证是必须的，原因如下：

| 场景 | 说明 |
|------|------|
| **绕过前端的 API 调用** | 外部系统或开发者可以直接调用 `POST /admin/stores/:id` API，绕过 Dashboard UI |
| **并发竞争条件** | 两个请求同时修改默认币种，可能导致数据竞态 |
| **历史数据不一致** | 之前版本的代码可能允许创建多个默认币种，数据库中已存在脏数据 |
| **单一可信源原则** | 业务规则的验证应该在服务端（后端），前端只是"优化体验" |
| **API 契约** | API 应该是自包含的，不应该依赖调用方的"善意" |

### 4.4 前端"看起来安全"但实际可能出问题的场景

假设有以下场景：

1. **数据库中已有两个默认币种**（历史脏数据）
   - 前端加载 `store.supported_currencies` 时，`find((c) => c.is_default)` 可能返回任意一个
   - 用户修改其他字段（如 `default_region_id`），不涉及币种
   - 前端转换时：`is_default: c.currency_code === default_currency_code`
   - 如果数据库中有两个 `is_default: true`，但 `default_currency_code` 只匹配其中一个
   - 转换后的数据中，原本两个都是 `true` 的币种，现在一个是 `true`，一个是 `false`
   - 这是**修正**操作，不会触发错误

2. **通过 API 直接发送恶意数据**
   ```json
   {
     "supported_currencies": [
       {"currency_code": "USD", "is_default": true},
       {"currency_code": "EUR", "is_default": true}
     ]
   }
   ```
   - 这种情况下，前端根本没有参与
   - 后端验证会立即捕获并抛出错误

## 五、对 Store 和 Price Preferences 的影响

### 5.1 对 Store 本体的影响

当更新以下字段时，直接修改 `Store` 表：

| 字段 | 数据库字段 | 说明 |
|------|-----------|------|
| `default_region_id` | `default_region_id` | 默认区域 ID |
| `default_sales_channel_id` | `default_sales_channel_id` | 默认销售渠道 ID |
| `default_location_id` | `default_location_id` | 默认库存位置 ID |

### 5.2 对 StoreCurrency 的影响

`supported_currencies` 通过 `upsertWithReplace` 操作 `StoreCurrency` 关联表：

- **新增币种**: 插入新的 `StoreCurrency` 记录
- **更新币种**: 更新现有记录的 `is_default` 字段
- **删除币种**: 移除不再存在于数组中的 `StoreCurrency` 记录

### 5.3 对 Price Preferences 的影响

当 `supported_currencies` 包含 `is_tax_inclusive` 字段时，会触发 `updatePricePreferencesAsArrayStep`：

```typescript
return data.input.update.supported_currencies!.map((currency) => {
  return {
    attribute: "currency_code",
    value: currency.currency_code,
    is_tax_inclusive: currency.is_tax_inclusive,
  }
})
```
`update-stores.ts:74-80`

这会：
1. 以 `attribute: "currency_code"` 和 `value: {currency_code}` 为 key
2. 查询或创建 `PricePreference` 记录
3. 更新 `is_tax_inclusive` 字段

**注意**: `is_tax_inclusive` 在 Workflow 中被分离处理，不会存储在 `StoreCurrency` 表中，而是存储在独立的 `PricePreference` 表中。

## 七、总结

1. **数据流**: 前端表单 → API 路由 → Workflow → Step → Module Service → 数据库

2. **默认币种的特殊处理**: 
   - 前端将单选的 `default_currency_code` 转换为 `supported_currencies` 数组
   - 每个币种的 `is_default` 被设置为 `c.currency_code === default_currency_code`

3. **验证层级**:
   - **API 层**: 只有 Zod 类型验证
   - **Module Service 层**: 包含完整的业务规则验证（包括"多个默认币种"检查）

4. **为什么后端必须验证**:
   - 可能绕过前端直接调用 API
   - 并发竞争条件
   - 历史数据一致性问题
   - 单一可信源原则（SSOT）
   - API 应该自包含、自验证

5. **对 Price Preferences 的影响**:
   - `is_tax_inclusive` 字段在 Workflow 中被分离
   - 通过 `updatePricePreferencesAsArrayStep` 独立更新
   - 存储在 `PricePreference` 表而非 `StoreCurrency` 表
